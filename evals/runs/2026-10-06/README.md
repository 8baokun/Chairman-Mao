> 验证对象：台账 4.2 节「待实测验证」项 E1 / E2 / E3（原标注：规则已落地，但未重跑 evals 实测，不得标 ✅）
> 验证问题：**规则写进 SKILL.md，agent 的实际输出是否真的变了？**

## 一、验证设计

| 要素 | 做法 |
|---|---|
| **对照法** | paired —— 同一组题，v7.0（基线）与 v8.0（现行）各跑一遍，共 6 份输出 |
| **环境隔离** | 用 `git worktree add D:/workbuddy/_mao_v70 c7ad4c9` 造 v7.0 快照副本，子 agent 在各自目录下按各自 `SKILL.md` 执行，互不干扰 |
| **题面** | E1 人工智能 / E2 气候变化 / E3 社交媒体（取自 `evals/validation-edge-test.md`） |
| **双盲** | 发现台账泄漏见 §二 → 对 6 份输出做**版本脱敏 + 逐题随机编号**，judge 不知道哪个是新版本；映射存 `blind-mapping.json` 事后开封 |
| **评判** | 3 位独立 judge，统一量规四维度（措辞恰当性 / 时代局限性声明 / 出处可核验性 / 整体质量），E3 第一维度换成「结构性张力处理」；judge 被要求**附文本证据行号** |

## 二、过程中发现的方法论问题：台账本身会泄漏答案

首轮跑完后核查发现，**v7.0 环境的 agent 也承认了 P-2 张力**——因为它读了 `evals/TARGET-GAP.md`，而台账里白纸黑字写着这条差距。

> 结论：**台账是一个泄漏答案的强控制器**。只要可被 agent 读到，对照组的差异就会被抹平，验证失去效力。

处置：本轮改为双盲（版本标识替换 + 随机编号 + 删除含台账内部编号的行）。后续维护须注意——**评测时应隔离台账，或至少不将其列为工作流的加载对象**（当前 Step 0–4 并不加载台账，本次泄漏发生在 v7.0 环境的留痕环节，属 agent 自主读取）。

## 五、关键行为差异（judge 原话摘录与归纳）

1. **范畴审查发生的时点不同**（E1）
   v8.0 在**取法之前**先做模型排除并给出理由（"AI 不是人格化对手，敌我框架与兵力框架在此均不适用"）；v7.0 取法后不再回查范畴，把《论持久战》的强弱对抗语义直接用到 AI 上（"未战先降""一战定乾坤"）。
   → **P-1 的措辞规则确实改变了行为**，且改变发生在决策链前端，不是事后修辞。

2. **面对语料盲区的两种姿势**（E2）
   两者都承认"语料中关于气候的直接论述为零"。v8.0 承认后**回头在语料内搜寻仅有的合法抓手**并据此限定能说什么；v7.0 承认后转身在行文里把自然系统写成"敌"，继之以"决战/歼敌/我强敌弱"。
   judge 原话：*"同一份诚实，一个落成了自律，一个落成了自相矛盾。"*

3. **自我证伪的方式不同**（E1）
   v8.0 给出可使结论**作废**的条件（含框架级作废）；v7.0 给出的是使结论**需要修正**的条件，本质仍是"本框架仍适用，只是要打折"。

## 六、结论：E1 / E2 / E3 判定为 ✅

判据满足台账纪律——**已重跑实测，且由盲评证明输出行为确有改善**：

- E1：措辞、证据分级、证伪条件三项胜出
- E2：措辞由"失当"转为"得当"（质的差别，非程度差别）
- E3：张力处理由"承认"进阶为"承认 + 分层给出适用边界"，并主动驳斥抹平式类比
